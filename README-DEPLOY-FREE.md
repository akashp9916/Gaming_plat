# CloudPlay demo deployment (free-tier target)

This package is for a public **demo website**, not real cloud gaming. `DEMO_MODE=1` creates sample records and session start returns a preview page instead of launching a GPU container.

## 1. Local test on Windows

Requirements: Docker Desktop running, Git, and a MongoDB connection for hosted deployment. For local testing, Compose runs MongoDB for you.

In PowerShell, from this folder:

```powershell
Copy-Item .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Paste the generated value into `.env` as `JWT_SECRET`. Then:

```powershell
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 api
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod http://localhost:8000/games
```

Open `http://localhost:8000/`. Stop with `docker compose down`. To remove the local Mongo data too, use `docker compose down -v` (this deletes the local database).

## 2. Create a free MongoDB database

Create a free cluster in MongoDB Atlas: https://www.mongodb.com/cloud/atlas/register
Create a database user, allow network access as required by Atlas, and copy the driver connection string. Replace its password placeholder and add the database name if needed. Treat the URI as a secret.

## 3. Push this folder to GitHub

Create an empty GitHub repository. From this folder in PowerShell:

```powershell
git init
git add .
git status
git commit -m "Prepare CloudPlay demo deployment"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

Check `git status` before committing and make sure `.env` is not included. Do not upload your local `venv` folder.

## 4. Deploy on Render

1. Open https://dashboard.render.com/ and connect GitHub.
2. Choose **New → Blueprint** and select this repository (the root must contain `render.yaml`).
3. Enter `MONGO_URI` from Atlas and your `ADMIN_EMAILS` when prompted. `JWT_SECRET` is generated by the blueprint.
4. Deploy and wait for the build to finish.
5. Use the actual service URL Render assigns; the `PUBLIC_HOST` in `render.yaml` is a placeholder and can be updated to the actual URL in Render settings.

Test:

```text
https://YOUR-ACTUAL-SERVICE.onrender.com/health
https://YOUR-ACTUAL-SERVICE.onrender.com/games
https://YOUR-ACTUAL-SERVICE.onrender.com/
```

## Limitations and important safety notes

- Free web services can sleep when idle, so the first request may be slow. Free-tier terms and availability can change.
- Free databases have storage, throughput, and backup limitations. Use this for a demo only.
- The app's demo sessions do not run games or provide real video streaming.
- Before production: review authentication, CORS, rate limits, session cleanup, database access, logs, and account recovery.
- Do not expose or mount the Docker socket for this demo. Do not commit `.env`, database credentials, or access tokens.
- Only host games you own or have a licence to distribute/stream.
